# Установка сайта отчётов на хостинг

Сайт содержит отчёты «Накопленная выручка месяца» и «Задолженность по роялти». Переключение - меню вверху слева.

> **Сайт уже установлен прежним архивом?** Переустанавливать не нужно. Настройте автоматическую выкладку по инструкции `DEPLOY.md` в репозитории и запустите её: код обновится, а `config.php`, пароль, ключ Google и настройки сохранятся. После первой выкладки нажмите в «Настройках» **«Обновить все отчёты»**. Устаревшие файлы `lib/builder.php`, `templates/dashboard.php`, `assets/dashboard.js` можно удалить, но мешать они не будут.

Время: 40-60 минут. Нужны:
- доступ к панели хостинга;
- Google-аккаунт для создания сервисного аккаунта;
- помощь владельца таблиц, чтобы открыть к ним доступ.

## Что понадобится

| Что | Где взять |
|---|---|
| Архив `ns-dashboard.zip` | Прислан вместе с этой инструкцией |
| Ключ настройки (`setup_key`) | В файле `config.php` внутри архива |
| Хостинг с PHP 7.4 или новее (лучше 8.1+), расширения curl, openssl, mbstring | Обычно уже включены. Версия PHP выбирается в панели хостинга |
| Домен с HTTPS | Уже есть |

## Шаг 1. Создать сервисный аккаунт Google (15 мин)

Сервисный аккаунт - это «робот» с собственным email. Сайт читает таблицы от его имени.

1. Откройте https://console.cloud.google.com/ и войдите в любой Google-аккаунт.
2. Вверху нажмите выбор проекта → **New Project**. Название, например, `ns-dashboard` → **Create**. Убедитесь, что выбран новый проект.
3. Меню ☰ → **APIs & Services** → **Library**. Найдите **Google Sheets API** → **Enable**.
4. Меню ☰ → **IAM & Admin** → **Service Accounts** → **Create service account**.
   - Name: `dashboard-reader` → **Create and continue**.
   - Роли не нужны → **Continue** → **Done**.
5. Откройте созданный аккаунт → вкладка **Keys** → **Add key** → **Create new key** → **JSON** → **Create**.
   Скачается файл вида `ns-dashboard-xxxx.json`. Это ключ: храните его как пароль и никому не пересылайте.
6. Скопируйте email аккаунта, например `dashboard-reader@ns-dashboard.iam.gserviceaccount.com`.

> Если Google при создании ключа пишет, что создание ключей запрещено политикой организации, создайте проект в личном аккаунте Gmail, а не в корпоративном Google Workspace.

## Шаг 2. Открыть доступ к таблицам (делает владелец таблиц)

Владелец файлов «Отчет УК по выручке» должен выдать email из шага 1.6 права **Читатель** (без уведомления).

- **Лучший вариант:** открыть доступ к **папке**, где лежат текущий файл и все архивы. Тогда новые архивы, созданные в этой папке, будут доступны автоматически.
- **Если файлы не в одной папке:** открыть доступ к текущему файлу и к архивам минимум за 13 последних месяцев, включая декабрь 2025. Каждый новый архив придётся открывать отдельно.
- **Реестр задолженности** («Реестр задолженности Не школа») - тоже доступ «Читатель». Для `dashboard-reader@annular-form-160606.iam.gserviceaccount.com` он уже открыт.

## Шаг 3. Загрузить файлы на хостинг (10 мин)

1. В панели хостинга откройте **Файловый менеджер**. Перейдите в папку сайта: обычно `public_html`, `www` или `ваш-домен/public_html`.
   - Если сайт будет в подпапке (например `https://домен/report/`), создайте папку `report` и работайте в ней.
2. Загрузите `ns-dashboard.zip` и распакуйте его кнопкой «Распаковать» / «Извлечь».
3. Проверьте, что в папке сайта лежат `index.php`, `admin.php`, `cron.php`, `config.php` и папки `assets`, `lib`, `templates`, `data`. Именно эти файлы, а не одна вложенная папка с ними.
4. Удалите `ns-dashboard.zip` с хостинга.
5. Если на хостинге нет распаковки, распакуйте архив у себя и загрузите файлы через FTP (FileZilla). Данные FTP есть в панели хостинга.
6. В панели хостинга выберите PHP 8.1 или новее для этого сайта.

## Шаг 4. Первичная настройка (5 мин)

1. Откройте `https://ваш-домен/setup.php`.
2. Введите:
   - **Ключ настройки** - значение `setup_key` из `config.php`. Файл можно открыть в файловом менеджере;
   - **логин**;
   - **пароль** - от 10 символов.
3. После сохранения откроется страница входа. Войдите.
4. Страница `setup.php` после этого больше не работает. Это нормально.

## Шаг 5. Подключить Google и загрузить данные (5 мин)

1. Нажмите **Настройки** (справа вверху).
2. Раздел **Доступ к Google** → выберите JSON-ключ из шага 1.5 → **Загрузить ключ**.
3. Раздел **Источники данных**: проверьте, что указана ссылка на текущий файл «Отчет УК по выручке». Декабрь 2025 уже прописан в дополнительных ссылках.
4. Нажмите **Обновить все отчёты**. Первая загрузка - 13 таблиц выручки и реестр задолженности, это 30-90 секунд.
5. В разделе **Состояние отчётов** у обоих отчётов должно быть «успешно». У выручки в «Источниках» - 13 месяцев.
   Если есть предупреждения, смотрите таблицу «Если что-то не так» ниже.

## Шаг 6. Проверить защиту данных (1 мин)

Откройте в браузере `https://ваш-домен/data/settings.json` и `https://ваш-домен/config.php`.

- **Ожидается:** ошибка 403 «Forbidden» (или 404) для файла настроек и пустая страница для config.php.
- **Если открылся текст с настройками**, хостинг не применяет файлы `.htaccess` (сервер nginx без Apache). Тогда:
  1. создайте папку **вне** публичной папки сайта, например `/home/логин/ns-data`;
  2. в `config.php` замените строку `'data_dir' => __DIR__ . '/data',` на `'data_dir' => '/home/логин/ns-data',`;
  3. снова откройте `setup.php` и повторите шаги 4-5;
  4. удалите старую папку `data` из папки сайта.

## Шаг 7. Ежедневное автообновление (5 мин)

В панели хостинга найдите **Планировщик заданий / Cron**.

- **Если можно указать команду**, укажите команду со страницы «Настройки» → «Ежедневное обновление». Например:
  ```
  php /home/логин/ваш-домен/public_html/cron.php
  ```
  На некоторых хостингах путь к PHP указывается с версией, например `/usr/local/bin/php8.1`. Его подсказывает сам планировщик.
- **Если можно указать только ссылку**, укажите ссылку `https://ваш-домен/cron.php?key=...` со страницы «Настройки».

Расписание: **каждые 2 часа с 07:00 до 23:00**. Минуты: `0`, часы: `7-23/2`, остальное `*`.
Так отчёт подхватит вчерашний день, когда бот допишет его в таблицу.

Проверка: на следующий день в «Настройки» → «Журнал» должны появиться строки «Обновление (cron): ок».

## Ежемесячно: 1-го числа

| Что происходит | Что сделать |
|---|---|
| 1-го числа срез - последний день прошлого месяца | Ничего: отчёт показывает закрытый месяц |
| Появился файл нового месяца с новой ссылкой | «Настройки» → «Источники и параметры: Накопленная выручка месяца» → вставить ссылку → «Сохранить» → «Обновить». Галочка «сохранить прежнюю как архив» перенесёт старую ссылку в архив автоматически |
| Архив прошлого месяца добавлен на лист «Предыдущие месяца» | Ничего: отчёт найдёт его сам |
| В «Состоянии данных» предупреждение «архивный файл не найден» | Добавить ссылку на архив в поле «Дополнительные ссылки на архивы», например `2026-11 https://docs.google.com/...` |

## Если что-то не так

| Сообщение | Причина и решение |
|---|---|
| `Google Sheets (403 ...)` | Таблица не открыта для email сервисного аккаунта (шаг 2) или не включён Google Sheets API (шаг 1.3) |
| `Google Sheets (404 ...)` | Неверная ссылка на таблицу или нет доступа |
| `Google не выдал токен доступа` | Загружен не тот файл ключа или ключ удалён в Google Cloud - создайте новый (шаг 1.5) |
| `Не найден заголовок «Выручка (рубли)»` | В таблице переименован столбец. Отчёт берёт столбец H, но проверьте структуру |
| `нет данных - добавьте ссылку на архив` | Нужного месяца нет ни в листе «Предыдущие месяца», ни в дополнительных ссылках |
| Сайт бесконечно перенаправляет | В `config.php` поставьте `'force_https' => false` |
| `Обновление уже выполняется` | Подождите 1-2 минуты: идёт загрузка |
| Белая страница или «Внутренняя ошибка» | Проверьте версию PHP (7.4+) и что папка `data` доступна для записи (права 750 или 755) |
| Забыт пароль | Удалите `data/settings.json` в файловом менеджере и пройдите `setup.php` снова. Ссылки по умолчанию восстановятся, ключ Google останется |

## Обновление кода сайта в будущем

Сайт обновляет себя сам: «Настройки» → «Обновление кода сайта». Новые версии из GitHub ставятся при запуске задания планировщика (шаг 7) или кнопкой «Обновить код сейчас», только если для них прошли автотесты; есть откат. Подробно - `DEPLOY.md` в репозитории. Вручную: заменить файлы, **не трогая** `config.php` и папку `data`.
