# Автоматическая выкладка сайта отчётов

После настройки обновления попадают на хостинг так:

1. Изменения сохраняются в рабочую ветку репозитория.
2. Вы просматриваете их и сливаете в ветку `main`.
3. GitHub сам проверяет код автотестами и загружает изменённые файлы на хостинг по FTP.

Распаковывать архивы больше не нужно. `config.php` (ключи) и папка `data` (настройки, пароль, данные) на сервере **никогда не перезаписываются**.

## Настройка (один раз, 20-30 минут)

### 1. FTP-доступ на хостинге REG.ru

Итог шага - четыре значения для GitHub: адрес сервера, логин, пароль и папка сайта.

Названия пунктов меню ниже - по справке REG.ru. В разных версиях панелей они могут немного отличаться.

#### 1.1. Узнайте, какая у вас панель управления

1. Войдите в [личный кабинет REG.ru](https://www.reg.ru/user/account) → **Хостинг** → откройте свою услугу.
2. Перейдите в панель управления хостингом (ссылка или кнопка на странице услуги).
3. Определите панель по виду и логотипу. У REG.ru бывает три варианта:

| Панель | Как узнать | Где лежит сайт на сервере |
|---|---|---|
| **ispmanager** (самая частая) | слева меню «Сайты», «Менеджер файлов», «FTP-пользователи» | `/var/www/u1234567/data/www/ваш-домен.ru/` |
| **cPanel** | плитки разделов «Файлы», «Домены», «Учётные записи FTP» | `/var/www/u1234567/ваш-домен.ru/` |
| **Plesk** | слева «Сайты и домены», у домена кнопка «Доступ по FTP» | `/var/www/vhosts/u1234567.plsk.regruhosting.ru/ваш-домен.ru/` |

`u1234567` - ваш логин хостинга. Он виден в личном кабинете на странице услуги и в письме о подключении хостинга.

Точную папку своего сайта посмотрите в панели: ispmanager - раздел **Сайты**, столбец «Корневая директория»; cPanel - **Домены**, столбец «Корень документа»; Plesk - **Сайты и домены**, строка «Корень документа» у домена.

> Если отчёты будут на поддомене (например `report.ваш-домен.ru`), у поддомена своя папка - смотрите именно её.

#### 1.2. Создайте отдельного FTP-пользователя только для папки сайта

Основной FTP-логин `u1234567` видит **весь** хостинг, включая другие сайты. Для GitHub создайте отдельного пользователя с доступом только к папке отчётов. Если его пароль когда-нибудь утечёт, остальные сайты не пострадают.

**ispmanager**
1. Меню слева **FTP-пользователи** (в старых версиях - **Файлы → Учётные записи FTP**) → **Создать**.
2. Имя: например `deploy`. Панель добавит префикс, итоговый логин будет вида `u1234567_deploy`. Запишите его полностью.
3. Пароль: сгенерируйте длинный (кнопка генерации рядом с полем) и сохраните в менеджере паролей.
4. **Домашняя директория:** по умолчанию стоит `/`, то есть весь хостинг. Обязательно выберите папку сайта: `www/ваш-домен.ru` (без ведущего слеша).
5. Нажмите **Ok**.

**cPanel**
1. **Файлы → Учётные записи FTP** → блок «Добавить учётную запись FTP».
2. Логин: `deploy`, домен - ваш. Итоговый логин будет вида `deploy@ваш-домен.ru`.
3. Пароль - длинный, сгенерированный.
4. **Каталог:** cPanel сам подставит `deploy` или похожий путь. Замените его на папку сайта, например `ваш-домен.ru`.
5. Квота - «Не ограничено» → **Создать учётную запись FTP**.

**Plesk**
1. **Сайты и домены** → ваш домен → **Доступ по FTP** → **Добавить учётную запись FTP**.
2. Имя: `deploy`, пароль - длинный, сгенерированный.
3. **Домашний каталог:** выберите корень сайта (`/ваш-домен.ru` или `/httpdocs` - смотря что указано в «Корне документа»).
4. **OK**.

#### 1.3. Адрес FTP-сервера

Укажите **имя сервера хостинга, оканчивающееся на `.hosting.reg.ru`**, например `server123.hosting.reg.ru`. IP-адрес и ваш домен **не подойдут**: сертификат защищённого FTP у REG.ru выдан на имена `*.hosting.reg.ru`. С IP выкладка падает с ошибкой `ERR_TLS_CERT_ALTNAME_INVALID ... IP: *** is not in the cert's list`.

Как узнать имя сервера (подойдёт любой способ):
- **Личный кабинет REG.ru** → Хостинг → ваша услуга: в информации об услуге и доступах указан сервер.
- **Письмо о подключении хостинга** - там указан сервер.
- **По IP-адресу:** на компьютере откройте командную строку (Windows: Win+R → `cmd` → Enter; macOS: Терминал) и выполните `nslookup ВАШ_IP`. В строке `name =` будет имя вида `serverNNN.hosting.reg.ru`.

#### 1.4. Проверьте доступ вручную (5 минут, сэкономит время на ошибках)

Установите [FileZilla](https://filezilla-project.org/) → **Файл → Менеджер сайтов → Новый сайт**:
- Протокол: **FTP**;
- Хост: имя сервера из шага 1.3, порт `21`;
- Шифрование: **Использовать явный FTP через TLS** (так рекомендует REG.ru);
- Тип входа: **Нормальный**, пользователь и пароль из шага 1.2.

После **Соединиться**:
- если FileZilla спросит про сертификат - посмотрите, на какое имя он выдан. Если не на то, что вы ввели в «Хост», впишите это имя в «Хост»;
- откроется папка пользователя. Если домашняя директория - папка сайта, вы сразу увидите `index.php`, `admin.php`, папки `lib`, `reports` (или пустую папку, если сайт ещё не установлен).

#### 1.5. Что записать для GitHub

| Секрет | Значение для REG.ru |
|---|---|
| `FTP_SERVER` | имя сервера хостинга из шага 1.3 - без `ftp://` и без папок |
| `FTP_USERNAME` | логин FTP-пользователя целиком: `u1234567_deploy` (ispmanager), `deploy@ваш-домен.ru` (cPanel), `deploy` (Plesk) |
| `FTP_PASSWORD` | пароль этого пользователя |
| `FTP_DIR` | `./` - если домашняя директория пользователя = папка сайта (как в шаге 1.2) |

`FTP_DIR` для случая, если вы всё же используете основной логин `u1234567`, который видит весь хостинг (не рекомендуется):

| Панель | `FTP_DIR` |
|---|---|
| ispmanager | `www/ваш-домен.ru/` |
| cPanel | `ваш-домен.ru/` |
| Plesk | `ваш-домен.ru/` или `httpdocs/` - как в «Корне документа» |

Слеш на конце `FTP_DIR` обязателен.

### 2. Ветка `main`
1. Откройте https://github.com/pisimonov/test/branches → **New branch**. Название `main`, источник - `claude/loving-ptolemy-wpw9a2` → **Create**.
2. Откройте **Settings → General → Default branch**, выберите `main` и подтвердите.

### 3. Секреты
Откройте **Settings → Secrets and variables → Actions**.

Вкладка **Secrets → New repository secret**, по одному:

| Имя | Значение |
|---|---|
| `FTP_SERVER` | адрес FTP-сервера |
| `FTP_USERNAME` | логин FTP |
| `FTP_PASSWORD` | пароль FTP |
| `FTP_DIR` | папка сайта со слешем на конце; для REG.ru - см. шаг 1.5 (обычно `./`) |

Вкладка **Variables → New repository variable**:

| Имя | Значение |
|---|---|
| `SITE_URL` | адрес сайта без слеша на конце, например `https://report.example.ru`. Нужен, чтобы после выкладки проверить, что сайт ответил новой версией |
| `FTP_PROTOCOL` | только если хостинг не поддерживает защищённый FTPS: `ftp` |
| `FTP_SECURITY` | только если выкладка падает с ошибкой сертификата, а исправить `FTP_SERVER` на имя сервера не получается: `loose`. Соединение останется зашифрованным, но без проверки подлинности сервера |

Секреты видны только GitHub Actions. Ни в коде, ни в журналах они не показываются.

### 4. Подтверждение выкладки вручную (рекомендуется)
Откройте **Settings → Environments → production** (окружение появится после первого запуска; его можно создать и заранее кнопкой **New environment**). Включите **Required reviewers** и укажите себя. Тогда каждая выкладка ждёт вашей кнопки **Approve**.

### 5. Первый запуск

Делайте с компьютера, в браузере на весь экран. На телефоне и в узком окне левая колонка со списком сценариев скрыта.

Ниже - **упрощённые схемы** экранов GitHub (не настоящие скриншоты): надписи и расположение кнопок те же, оформление проще.

**Самый короткий путь** - откройте прямую ссылку, она ведёт сразу на экран 2:
https://github.com/pisimonov/test/actions/workflows/deploy.yml

**5.1. Откройте вкладку Actions.** На странице репозитория https://github.com/pisimonov/test в верхнем ряду вкладок (Code, Issues, Pull requests, **Actions**, …, Settings) нажмите **Actions** (метка 1).

![Экран 1](docs/deploy/s1.png)

**5.2. Выберите сценарий.** Откроется страница Actions. Слева - колонка с заголовком **Actions**, кнопкой **New workflow** и списком: **All workflows**, под ним **Выкладка сайта**. Нажмите **Выкладка сайта** (метка 2).

Справа появится серая полоса с текстом *This workflow has a workflow_dispatch event trigger.* и кнопкой **Run workflow ▾** у правого края (метка 3). Нажмите её.

![Экран 2](docs/deploy/s2.png)

> Нет серой полосы и кнопки **Run workflow**? Значит, не выполнен шаг 2 (основная ветка - `main`) или у вашей учётной записи нет прав на запись в репозиторий.

**5.3. Выберите ветку и запустите.** Откроется окошко **Use workflow from**:
- в списке **Branch** выберите **`main`** (метка 4). Это обязательно: из другой ветки пройдут только тесты, а выкладка будет пропущена (статус *skipped*);
- нажмите зелёную кнопку **Run workflow** (метка 5).

![Экран 3](docs/deploy/s3.png)

**5.4. Откройте запуск.** Через 5-10 секунд под серой полосой появится строка **Выкладка сайта** с жёлтым кружком (идёт) - нажмите на неё. Если строка не появилась, обновите страницу (F5).

**5.5. Дождитесь тестов** - около минуты. Слева на странице запуска три задания:
- **Тесты (PHP 7.4)**;
- **Тесты (PHP 8.3)**;
- **Выкладка по FTP**.

Тесты должны стать зелёными ✓.

**5.6. Подтвердите выкладку** - только если в шаге 4 включили подтверждение. Появится жёлтая полоса *Waiting for review: production needs approval…* и кнопка **Review deployments** (метка 6):
1. нажмите **Review deployments**;
2. отметьте галочку **production** (метка 7);
3. нажмите **Approve and deploy** (метка 8).

![Экран 4](docs/deploy/s4.png)

**5.7. Проверьте результат.**
- Через 1-2 минуты у всех заданий зелёные ✓, у запуска - зелёная галочка.
- Первый запуск загружает все файлы, следующие - только изменённые.
- Откройте `https://ваш-домен.ru/health.php` - в ответе версия с сегодняшней датой. Та же версия видна в шапке страницы «Настройки» сайта.
- Если какое-то задание красное ✗: нажмите на него, раскройте шаг с красным крестиком и посмотрите текст ошибки. Сверьтесь с таблицей «Если что-то не так» ниже или пришлите текст (без паролей).

## Как выглядит обычное обновление

1. Я сохраняю изменения в ветку `claude/...` и пишу в чате, что поменялось.
2. На GitHub появляется жёлтая плашка **Compare & pull request**. Нажмите её, затем **Create pull request**. Список изменённых файлов будет во вкладке **Files changed**.
3. Нажмите **Merge pull request**.
4. Во вкладке **Actions** запускается «Выкладка сайта»:
   - тесты на PHP 7.4 и 8.3;
   - загрузка на хостинг;
   - проверка `SITE_URL/health.php`.

   Если тесты не прошли, на сайт ничего не попадает.

## Откат

В закрытом pull request нажмите **Revert** → **Create pull request** → **Merge**. Сайт вернётся к предыдущей версии тем же путём.

## Если что-то не так

| Ошибка в журнале Actions | Что сделать |
|---|---|
| `530 Login incorrect` | Проверьте `FTP_USERNAME` и `FTP_PASSWORD`. На REG.ru логин указывается целиком, с префиксом: `u1234567_deploy` (ispmanager) или `deploy@ваш-домен.ru` (cPanel) |
| `ECONNREFUSED`, `ETIMEDOUT` | Неверный `FTP_SERVER` или хостинг блокирует FTP извне - проверьте в панели хостинга |
| `Hostname/IP does not match certificate`, `self signed certificate` | В `FTP_SERVER` указан домен или IP, а сертификат выдан на имя сервера хостинга. Впишите имя сервера (шаг 1.3). Если не помогло - переменная `FTP_SECURITY` = `loose` |
| Другая ошибка TLS / `FTPS` | Проверьте вход в FileZilla с «явным FTP через TLS» (шаг 1.4). Если там тоже не работает - переменная `FTP_PROTOCOL` = `ftp` |
| Соединение есть, но обрывается при передаче (`timeout`, `ECONNRESET` в середине) | Повторите запуск (**Re-run jobs**): выкладка продолжит с места остановки. Если повторяется - напишите в поддержку REG.ru, что нужен пассивный режим FTP для внешних подключений |
| Файлы оказались не в той папке | Исправьте `FTP_DIR` (шаг 1.5) или домашнюю директорию FTP-пользователя (шаг 1.2). Лишние файлы удалите в файловом менеджере хостинга |
| Сайт открывается, но показывает старую версию или «Index of» | Файлы легли рядом с папкой сайта, а не в неё: сверьте «Корневую директорию» домена в панели (шаг 1.1) с домашней директорией FTP-пользователя |
| «Сайт не ответил новой версией», `curl: (22) ... 404` | Файлы загружены, но не в ту папку, которую показывает домен из `SITE_URL`. В ispmanager → «Менеджер файлов» найдите, где лежат `health.php` и `.ftp-deploy-sync-state.json`, и сравните с «Корневой директорией» домена (раздел «Сайты»). Поправьте домашнюю директорию FTP-пользователя или `FTP_DIR`, удалите ошибочно загруженные файлы и перезапустите выкладку |
